# 01 · 历史之路 — Road to WebSockets

## 定义
WebSocket 是一种让客户端和服务器建立一条长期保持的连接，并通过这条连接进行双向、实时通信的技术。

WebSocket 连接最开始仍然通过一次 HTTP 请求/响应 来建立。握手成功后，这条连接就不会像普通 HTTP 请求那样立即结束，而是会一直保持打开状态。

此后，客户端和服务器都可以主动向对方发送数据，不需要每次通信都重新建立 HTTP 请求，因此非常适合聊天、实时通知、在线游戏、实时数据推送等场景。

可以简单理解为：HTTP 更像“你问我答”，WebSocket 更像“打通一条长期保持的电话线路”，双方随时都可以说话。

WebSocket 技术包含两个核心组成部分：

- WebSocket 协议支持客户端和服务器之间通过 Web 进行通信，并支持传输二进制数据和文本字符串。

- WebSocket API允许您执行必要的操作，例如管理 WebSocket 连接、发送和接收消息以及监听服务器触发的事件。

## WebSocket 和 HTTP

最主要的区别在于HTTP 是请求驱动的，而WebSocket是事件驱动的。有下面几点: 

- 信息交换模式: WebSocket采用双向,HTTP为请求-响应模式;

- 连接开销: WebSocket 建立连接需要一定的开销，而每条消息的开销极小。HTTP每次请求/连接的开销适中。

- 状态保留: WebSocket 具有会话状态, HTTP协议前后请求-响应无状态记录。

HTTP 和 WebSocket 的设计用途不同。例如，如果你的应用大量依赖 CRUD 操作，且用户无需快速响应更改，那么 HTTP 是一个不错的选择。另一方面，对于可扩展、低延迟的实时应用，WebSocket 才是最佳选择。

## WebSocket的使用案例和优势


### WebSocket 的使用案例大致分为两大类：

- 实时更新是指通信是单向的，服务器向客户端传输低延迟（且通常频繁）的更新数据。例如，实时体育赛事更新、警报、实时仪表盘或位置跟踪等等。

- 双向通信是指客户端和服务器都可以发送和接收消息。例如聊天、虚拟活动和虚拟教室（后两者通常包含投票、测验和问答等功能）。WebSocket 还可以用于支持多人同步协作功能，例如多人同时编辑同一文档。


### 使用 WebSocket 的一些主要好处

- 性能提升。WebSocket 只需要建立一次长连接，之后双方可以在这条连接上持续发送大量消息，而不需要每条消息都按照 HTTP 请求/响应的格式进行通信，因此每条消息的协议开销通常更小。这有助于节省带宽、降低延迟，并使 WebSocket 比 HTTP 更具可扩展性

- 可扩展性。WebSocket 负责提供实时双向通信的基础能力。在这个连接上如何组织业务数据、制定通信规则，以及是否增加压缩等能力，都可以通过子协议和扩展来实现。

- 快速响应时间。作为一种事件驱动技术，WebSocket 允许在客户端未请求的情况下传输数据。这一特性在客户端需要快速响应事件（尤其是无法预测的事件，例如欺诈警报）的场景中非常理想。

### WebSocket 的创建目的

WebSocket 的创建是为了解决 HTTP 在实时通信方面效率低下的问题。HTTP 每次请求-响应周期都需要建立一个新的连接。而 WebSocket 提供了一种持久的全双工连接，消除了轮询开销，实现了真正的实时数据交换。
